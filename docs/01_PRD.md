# 카페 판매·손익·재고 관리 프로그램 PRD

작성일: 2026-10-12  
상태: 1차 제품 범위 확정. 메뉴 수익성 및 단계 구분은 사용자 선택을 반영했고, 나머지 제품 운영 기준은 “모두 추천으로” 진행하라는 사용자 지시에 따라 담당자가 추천안으로 정했다. 계산식·화면·기술·상세 동작은 후속 설계 대상이다.

## 1. 목적과 핵심 흐름

카페 운영자가 판매와 비용을 기록하고, 어떤 메뉴가 수익에 도움이 되는지, 선택한 기간의 실적과 손익이 어떤지, 재료가 얼마나 남았는지 확인하는 웹 프로그램이다.

핵심 흐름은 **판매 기록 입력 → 메뉴별 수익성 확인 → 같은 기간의 손익과 기준일의 재료 잔량 확인**이다. 기록을 수정하거나 삭제한 뒤에도 관련 결과가 서로 맞아야 한다.

사용자는 비개발자인 카페 운영자를 기준으로 한다. 1차는 한 매장에서 한 사람이 매장 운영용 컴퓨터 한 대로 사용하는 최소 기능 제품(MVP)으로 한다. MVP는 핵심 흐름을 실제로 사용해 볼 수 있는 첫 버전이다. 첫 배포의 목표는 해당 컴퓨터에서 웹 프로그램을 사용하고 기록을 보존하는 것이다. 여러 기기에서의 접속과 공유는 2차로 둔다. 이는 자료의 사실이 아니라 추천안으로 선택한 제품 범위다.

이번 문서는 목적, 기능 범위, 자료의 제약, 완료 기준만 정리한다. 계산식, 화면 디자인, 기술 선택, 상세 처리 절차와 코드는 다음 단계에서 정한다.

## 2. 자료에서 확인한 사실

근거는 `date/데이터설명.md`, `date/매장운영데이터.json`, `date/매장운영데이터.xlsx`이다. 엑셀의 시트·열·기록 수와 JSON의 항목·기록 수를 읽어 확인했다.

- 매장명은 프렙 카페이며, 직접 구성한 **가상 매장 샘플**이다. 실제 영업 성과를 증명하는 자료가 아니다.
- 실적 기간은 2025-07-01부터 2026-09-18 마감까지다. 영업달력은 2026-09-30까지 있고, 9월 19일부터 30일까지는 미마감이다.
- 금액은 원이며 부가세 제외다. 재료 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록의 두 형식이다. 두 파일을 별도 실적으로 더하지 않는다.
- JSON의 `settings`는 비어 있다. 앞으로의 운영 기준이 합의되었다고 볼 수 없다.

## 3. 기획할 때 주의할 점

| 확인한 특성 | 요구사항에 미치는 영향 |
| --- | --- |
| 판매 한 줄은 날짜·메뉴·채널별 집계다 | 주문 건수, 고객 수, 개별 주문 내역으로 설명하면 안 된다 |
| 과거 판매가·할인·수수료·원가가 기록되어 있다 | 과거 값은 보존한다. 현재 기준 변경만으로 과거 기록을 바꾸지 않는다 |
| 구매가격은 묶음 전체 금액, 레시피는 한 메뉴의 사용량이다 | 묶음 가격과 개당 원가를 혼동하면 안 된다 |
| 포장 전용 레시피가 있다 | 매장 판매와 포장 판매의 원가·재료 사용 차이를 보존해야 한다 |
| 월비용계획과 일별 비용은 같은 비용의 다른 표현이다 | 둘을 별개 비용으로 중복 반영하면 안 된다. 자료의 일별 비용을 실제 결제 내역으로 표현해서도 안 된다 |
| 영업 여부와 마감 여부는 다른 정보다 | 휴무, 마감된 판매 0, 기록 누락, 미마감 날짜를 구분해야 한다 |
| 자료가 연도 전체를 포함하지 않는다 | 연간 조회라도 일부 기간의 실적임을 알려야 한다 |
| 재고기록은 입고 양수, 폐기 음수, 실사조정 양수·음수다 | 실제로 센 수량과 재고 차이 조정량을 같은 의미로 취급하면 안 된다 |
| 재료마다 g·ml·개를 쓴다 | 서로 다른 단위를 섞어 잔량을 설명하면 안 된다 |
| 재고는 특정 시점의 잔량이다 | 기간 중 판매량과 기간 말 재고를 구분해야 한다 |
| 빈칸은 해당 없음 또는 미입력이다 | 빈칸을 무조건 0으로 바꾸면 안 된다 |
| 납기와 여유 재고 일수는 영업일 기준이다 | 발주 참고 기능은 영업달력과 함께 검토해야 한다 |

파일에 있는 원가·수수료·비용 배분 결과는 과거 기록이다. 앞으로의 운영 기준은 8절의 제품 결정과 구분한다. 필요한 정보가 없으면 확정된 결과처럼 안내하지 않는 것을 요구한다.

## 4. 전체 요구와 확정한 단계 구분

사용자는 핵심 흐름부터 구현하는 추천안 A를 선택했다. 아래의 **1차 범위는 확정**하며, 2차 기능도 전체 제품 요구에서 유지한다. 2차는 추가 시간으로 진행하며 이번 4시간에 포함하지 않는다.

| 기능 | 1차 핵심 기능 | 2차 확장 기능 |
| --- | --- | --- |
| 제공 자료 사용 | 제공된 한 매장 샘플을 한 번 반영하고 기록을 조회 | 다른 자료 구조 지원 |
| 판매 관리 | 제공된 메뉴·매장/포장 구분으로 판매 입력·수정·삭제 | 취소·반품·복잡한 판매채널 대응 |
| 비용 관리 | 비용 입력·수정·삭제와 기간별 확인 | 반복 비용 계획, 월 계획 관리와 비교 |
| 메뉴 수익성 | 메뉴별 판매량·매출과 재료·포장·결제수수료를 반영한 수익성 확인 | 수익성 등급, 순위·추세 |
| 실적과 손익 | 일·월 조회, 기록된 범위의 실적·손익 확인 | 주·분기·반기·연간 조회, 기간 비교 |
| 예상 손익 | 미래 전망은 2차로 진행 | 예상 손익과 전망의 근거·대상 기간 확인 |
| 재고 관리 | 입고·폐기·실제 재고 기록, 기준일의 기록상 잔량 확인 | 재고 변동 이력의 분석, 조정 정책 확장 |
| 부족 재료 | 기록상 잔량 확인까지 포함 | 합의한 기준의 부족 재료 안내와 필요한 발주량 참고 |
| 엑셀 업무 | 운영 중 양식 다운로드·가져오기는 2차로 진행 | 판매·비용 양식 다운로드와 가져오기, 이후 재고까지 확장 |
| 저장·백업·복원 | 작업 기록 저장, 수동 백업·복원 | 자동 백업, 여러 기기에서 사용 |
| 기준정보 | 제공된 메뉴·재료·레시피·가격이력을 활용 | 메뉴·재료·레시피·가격이력의 직접 관리 |

제공 자료를 처음 반영하는 것과 운영 중 새 엑셀 기록을 가져오는 것은 별개의 요구다. 1차는 전자만 포함한다. 사용자가 선택한 범위에 따라 운영 중 엑셀 가져오기는 2차로 진행한다.

메뉴 수익성은 메뉴 간 판단을 돕는 결과이고, 기간 손익은 매장 전체의 상태를 보는 결과다. **사용자 합의: 메뉴 수익성에는 재료·포장·결제수수료를 포함하고, 임대료·인건비 같은 공통 비용은 메뉴별로 나누지 않고 매장 전체 기간 손익에서 확인한다.** 매장 손익의 비용 범위와 새 기록에 필요한 정보는 8절의 추천 결정에 따른다. 미래 예상 손익과 이미 입력한 기록의 손익도 구분한다.

## 5. 1차 기능의 제품 요구사항

아래 항목은 확정한 1차 기능이다. 결과의 의미는 8절의 제품 결정에 따르며, 구체적인 계산과 동작은 다음 설계 단계에서 정한다.

| 번호 | 사용자가 할 수 있어야 하는 일 | 완료를 판단하는 기준 |
| --- | --- | --- |
| M1 | 제공 자료에서 판매·비용·재고 기록을 확인한다 | 엑셀과 JSON이 중복 실적으로 반영되지 않고, 가상 자료와 기록 기간을 알 수 있다 |
| M2 | 판매 기록을 입력·수정·삭제한다 | 변경된 기록과 해당 메뉴·기간의 결과가 일치한다 |
| M3 | 비용 기록을 입력·수정·삭제한다 | 기간 손익에 합의된 범위로 반영되고 월 계획과 중복되지 않는다 |
| M4 | 메뉴별 판매량·매출·수익성을 확인한다 | 재료·포장·결제수수료와 매장/포장 차이를 반영하며, 공통 비용이 메뉴 수익성에 포함되지 않음을 이해할 수 있다 |
| M5 | 일·월 실적과 손익을 확인한다 | 미마감·누락·부분 기간을 확정 실적이나 판매 0으로 오해하지 않는다 |
| M6 | 재료 입고·폐기·실제 재고를 기록하고 잔량을 확인한다 | 재료 단위와 잔량의 기준일을 알 수 있고, 실측값과 기록상 잔량의 의미가 구분된다 |
| M7 | 기록을 저장하고 수동으로 백업·복원한다 | 다시 사용해도 저장한 기록을 확인할 수 있고, 백업 시점의 기록과 관련 결과를 되찾을 수 있다 |

판매의 수정·삭제는 관련 수익성·손익·기록상 잔량에 일관되게 반영해야 한다. 사람이 센 실제 재고 기록은 판매 변경만으로 바꾸지 않는다. 실제 재고와 기록상 재고의 차이를 확인할 수 있어야 하며, 처리 순서와 조정 방법은 후속 설계에서 정한다.

## 6. 4시간 내 1차 구현의 범위와 시간 예산

**총 240분 안에 핵심 흐름을 사용해 볼 수 있는 최소 버전을 목표로 한다. 완료를 보장하는 견적은 아니다.** 제공 자료와 기존 항목, 이 문서의 운영 기준을 활용하는 최소 범위의 시간 예산이다.

| 단계 | 시간 예산 | 산출 목표 |
| --- | ---: | --- |
| 기획 | 25분 | PRD 확정과 결과 의미 확인 |
| 화면 설계 | 20분 | 입력부터 결과 확인까지의 흐름 정리 |
| 개발 | 140분 | M1~M7의 최소 기능 구현 |
| 검사 | 35분 | 핵심 흐름, 변경 반영, 기간 제약, 백업·복원 확인 |
| 배포 | 20분 | 합의한 사용 장소에서 접속·저장 확인 |
| 합계 | 240분 | 첫 사용 가능한 버전 |

한 매장·한 사용자, 제공된 메뉴와 레시피 활용, 일·월 조회, 미래 전망과 운영 중 엑셀 가져오기 제외를 작업량 제한으로 확정한다. 1차에 회원 관리, 권한, 여러 매장, 외부 주문·회계 연결, 자동 발주, 고급 그래프를 넣지 않는다.

기본 구현과 검사·배포 시간을 유지하기 어려우면 개발 전에 범위를 다시 협의한다. 백업·복원이나 검사 시간을 임의로 없애지 않는다. 기술·배포 환경은 후속 설계에서 확인하되, 운영용 컴퓨터 한 대에서 사용하는 제품 범위를 유지한다.

## 7. 1차 완료 시 확인할 사용자 결과

검사는 아래의 결과를 확인하는 수준으로 정의한다. 세부 검사 절차나 계산식은 후속 문서에서 정한다.

1. 판매를 입력한 운영자가 해당 메뉴의 수익성과 같은 기간의 손익·재료 잔량까지 확인할 수 있다.
2. 판매와 비용을 수정·삭제해도 기록과 관련 결과 사이에 설명되지 않는 차이가 생기지 않는다.
3. 포장 판매와 매장 판매의 재료 차이가 결과에 반영된다.
4. 입고·폐기·실제 재고 기록을 확인할 수 있고, 잔량의 단위와 기준일이 명확하다.
5. 2026년 9월 19일 이후의 미마감 날짜, 휴무, 누락, 실제 판매 0이 구분된다.
6. 일별 비용과 월비용계획이 중복되지 않으며, 제공 자료의 과거 기록이 합의 없이 바뀌지 않는다.
7. 저장 후 다시 사용할 수 있고, 백업에서 복원한 기록과 핵심 결과가 백업 당시와 일치한다.

## 8. 사용자 선택과 추천안으로 정한 제품 기준

근거: 2026-10-12 사용자가 메뉴 수익성 A, 1차 범위 A를 선택했고, 나머지는 “모두 추천으로 해줘”라고 지시했다. 아래에서 **사용자 선택**과 **담당자 추천 결정**을 구분한다. 담당자 추천 결정은 자료에 원래 들어 있던 정책이라는 뜻이 아니다.

| 항목 | 결정 내용 | 결정 근거와 추천 이유 |
| --- | --- | --- |
| 메뉴 수익성 | 재료·포장·결제수수료를 반영한다. 임대료·인건비 등 공통 비용은 메뉴별로 나누지 않는다 | 사용자 선택 A. 메뉴 자체의 수익성을 먼저 판단하고 공통 비용 배분의 복잡성을 줄인다 |
| 1차 범위 | 판매·비용 관리, 메뉴 수익성, 일·월 손익, 재고 기록·잔량, 저장·수동 백업·복원 | 사용자 선택 A. 판매 입력부터 손익·잔량 확인까지 이어지는 흐름을 우선한다 |
| 사용 규모와 장소 | 한 매장·한 사용자·운영용 컴퓨터 한 대 | 담당자 추천 결정. 사용자 관리와 기기 간 공유 작업을 줄여 4시간 범위를 유지한다 |
| 과거 기록 | 판매 당시 단가·원가·수수료와 기존 비용 기록을 보존한다. 사용자의 명시적 기록 수정은 허용한다 | 담당자 추천 결정. 현재 가격 변경으로 과거 실적이 달라지는 혼란을 줄인다 |
| 새 판매의 정보 | 판매 날짜·메뉴·매장/포장·수량·판매가·할인·수수료를 기록하고, 해당 시점의 제공 가격이력과 레시피를 원가 판단의 근거로 사용한다 | 담당자 추천 결정. 기존 기록과 의미를 맞춘다. 수수료는 확인된 금액을 사용하며, 샘플에서 임의의 고정 비율을 추정하지 않는다. 구체적인 계산식과 입력 동작은 후속 설계 대상이다 |
| 매장 기간 손익 | 재료·포장·결제수수료와 기록된 매장 운영 비용 8개 항목을 대상으로 한다. 폐기 손실도 매장 전체에서 확인할 대상으로 포함한다 | 담당자 추천 결정. 메뉴 자체의 수익성과 매장 운영 부담을 연결한다. 결과에는 비용 포함 범위와 미입력 정보를 알 수 있어야 한다. 재고 차이의 금액 평가 등 정밀한 재고 회계는 2차로 둔다 |
| 비용 기록과 월 계획 | 1차 손익에는 날짜별 비용 기록을 사용한다. 월 계획은 별도 지출로 반영하지 않는다. 직접 입력하는 비용도 해당 기간의 기록으로 관리한다 | 담당자 추천 결정. 제공 자료의 중복 반영을 막고 실제 결제 내역과 날짜별 배분 비용의 의미를 구분한다 |
| 재료 구매와 사용 비용 | 재료 입고에 관한 금액과 이미 원가로 반영한 재료 사용 비용을 같은 손익에서 중복 반영하지 않는다 | 담당자 추천 결정. 비용을 직접 기록할 때도 재료 구매와 일반 운영 비용을 구분해야 한다 |
| 실제 재고 활용 | 사람이 센 수량을 해당 시점의 실제 재고 확인 기준으로 삼는다. 기록상 잔량과의 차이는 구분해서 확인한다 | 담당자 추천 결정. 우유가 실제로 얼마나 남았는지 확인하는 목적을 우선한다. 시점 처리와 조정 방법은 후속 설계 대상이다 |
| 백업·복원 범위 | 판매·비용·초기재고·재고 기록과 메뉴·재료·레시피·가격이력·영업달력·공급사·월 계획·운영 기준 등 결과 재현에 필요한 전체 자료 | 담당자 추천 결정. 판매만 복원했는데 손익이나 잔량이 달라지는 문제를 막는다 |

원가 판단이나 폐기 손실 확인에 필요한 정보가 빠진 경우, 완전한 손익으로 표시하지 않는다. 그 정보의 확인 방법과 계산 기준은 다음 단계에서 설계한다. 제공 자료의 가상 매장 표시는 유지하며, 운영자가 새로 입력한 기록과 구분할 수 있어야 한다.

## 9. 2차 확장의 추천 방향과 미정 사항

2차에서도 담당자의 추천 방향을 사용하되, 이번 1차에 불필요한 세부 기준을 확정하지 않는다. 아래의 추천 방향은 제품 목표이며 구체적인 계산 정책은 미정이다.

| 확장 기능 | 추천 방향과 쉬운 예시 | 후속 설계에서 정할 내용 |
| --- | --- | --- |
| 엑셀 양식·가져오기 | 판매·비용부터 지원한다. 예: 하루 판매를 양식에 적어 한 번에 가져오기 | 양식의 세부 열, 중복·오류 처리, 기존 기록과의 관계 |
| 부족 재료·발주 참고 | 최근 영업의 사용량, 실제 재고, 입고까지 걸리는 시간, 여유 재고를 함께 참고한다. 예: 다음 입고 전 우유가 부족할지 확인 | 사용량을 보는 기간, 부족 판정과 발주량 계산, 구매 묶음 처리 |
| 예상 손익 | 이번 달 말까지의 전망부터 시작한다. 예: 9월 18일까지 기록으로 9월 말 상황 참고 | 전망 방법, 영업일·비용 계획 반영, 자료 부족 시 기준 |
| 기간 조회 확장 | 주는 월~일, 분기는 1~3월 등 달력 기준, 반기는 1~6월·7~12월, 연간은 1~12월을 추천 기본값으로 한다 | 기간 경계의 상세 처리와 비교 기준. 부분 기간 안내는 유지 |
| 기준정보 관리 | 새 메뉴·레시피·재료 가격의 변경을 관리한다 | 변경 적용일, 과거 기록과의 관계 |
| 저장·백업 확장 | 자동 백업과 여러 기기 사용으로 확장한다 | 사용 규모, 보관·복원 방식 |

## 10. 후속 문서로 넘길 내용

계산식, 수익성 표시 기준과 등급, 원가·폐기 손실의 세부 평가, 비용 배분 방식, 재고 시점과 조정 처리, 입력·수정·삭제의 상세 동작, 저장·복원의 상세 절차, 화면 디자인, 기술 선택, 검사 절차와 배포 방법은 이번 PRD에서 확정하지 않는다.

1차 제품 범위에 대한 추가 질문은 현재 없다. 구현에 필요한 상세 설계는 확정된 범위와 운영 기준 안에서 진행한다. 새로운 제품 요구나 4시간 범위 변경이 필요할 때만 별도로 협의한다.
