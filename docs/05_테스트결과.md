# 카페 관리 프로그램 테스트 결과

작성일: 2026-10-12  
대상: **EPIC 1~3**  
현재 판정: **EPIC 1 사용자 확인 완료 / EPIC 2·3 위임 검수 완료 — 전체 EPIC 완료 (로컬 기능 기준)**

1~6절은 EPIC 1 당시 기록, 7~9절은 EPIC 2 구현 직후 기록이다. 이후 검수 위임과 EPIC 3 결과는 10절부터 기록한다. 사용자 위임 이후에는 별도의 사용자 응답을 기다리지 않는다.

## 1. 검사 범위와 환경

PRD·FRD·TRD·개발 계획과 판매·메뉴 수익성 시안에 따라 판매 등록·수정·삭제, 메뉴별 수익성, 일·월 조회·필터·페이지, 초기 가상 자료 반영, 브라우저 저장을 구현했다.

EPIC 2·3의 비용·기간 손익·재고 조회·입고·폐기·실사·백업·복원 화면은 구현하지 않았다. 그 기능을 가짜 버튼이나 고정 숫자로 완료 처리하지 않았다. 판매의 재료 소진량은 공통 함수와 자동 검사로 확인했으며, 실제 잔량 화면 연결은 EPIC 2에서 다시 검사한다.

- 실행 환경: Node.js 24.19.0, React 19.3.0, Vite 8.3.4, TypeScript 7.0.2.
- 계산·저장 검사: Vitest 5.0.3, fake-indexeddb 6.2.5, decimal.js 10.6.0.
- 브라우저 검사: Playwright 1.64.0으로 설치된 Google Chrome 실행, 1440×1000 화면, 한국 날짜 기준.
- 검사 자료: 제공된 가상 샘플 및 별도의 작은 고정 자료. 원본 엑셀·JSON은 수정하지 않았다.
- 자동 브라우저 검사는 테스트마다 별도 임시 프로필을 사용했다. 사용자 확인용 인앱 브라우저의 기록은 자동 검사로 수정하지 않았다.
- 사용자 확인 주소: `http://127.0.0.1:5173/#/sales?mode=day&value=2026-09-19`.
- 로컬 서버 응답: HTTP 200 확인. 사용자 확인을 위해 서버를 유지한다. GitHub 업로드·Vercel 배포는 진행하지 않았다.

## 4. 검사 중 보완한 내용

- 채널 입력의 접근 이름을 ‘매장’, ‘포장’으로 명확히 하여 설명 문구와 혼동되지 않게 했다.
- 미마감일에 기록이 없으면 요약 카드에도 ‘조회 기록 없음’을 표시한다. 입력된 실제 0 금액과 구분한다.
- 새로 등록한 기록에 수정 이력이 있는 것처럼 표시하지 않도록 출처 문구를 보완했다.
- 자동 브라우저 검사의 표 합계 비교와 빈 목록 찾기를 실제 화면 범위에 맞게 수정한 뒤 6개 시나리오를 모두 재검사했다.

초기 브라우저 검사 실패 상태를 최종 통과로 가장하지 않았다. 수정 후 최종 실행에서 6개 모두 통과한 결과를 기록했다.

### 완료한 확인: U01 판매 등록

사용자 브라우저에 2026-09-19의 신규 판매 입력창을 열어 두었다. 메뉴 아메리카노·채널 포장·수량 10·단가 4,000·전체 할인 1,000·수수료 600을 입력하고 ‘기록 저장하기’를 누른다.

예상 결과: 입력창이 닫히고 ‘직접 입력’ 판매 한 줄이 나타난다. 순매출 39,000원·식재료비 4,968원·포장비 1,664원, 위쪽 판매 공헌이익 31,768원을 확인할 수 있다. 미마감이므로 잠정 표시가 남는다.

사용자 테스트 시작 화면: `docs/test-evidence/epic1-user-start.png`.

확인 결과: 2026-10-12 사용자가 “정상”이라고 응답했다. 안내한 판매 등록과 금액 확인을 통과로 기록한다. 이 응답으로 아직 안내하지 않은 검사나 EPIC 전체를 완료 처리하지 않는다.

### 완료한 확인: U02 새로고침 후 저장 유지

예상 결과: 2026-09-19 조회가 유지되고, 직접 입력한 아메리카노·포장·수량 10 기록이 남아 있다. 순매출 39,000원과 판매 공헌이익 31,768원도 그대로 표시된다.

확인 결과: 2026-10-12 사용자가 “정상”이라고 응답했다. 새로고침 후 조회 날짜와 저장 기록·금액 유지 확인을 통과로 기록한다.

### 완료한 확인: U03 메뉴 수익성 확인

왼쪽 ‘메뉴 수익성’을 누르고 조회 날짜가 2026-09-19인지 확인한다.

예상 결과: 아메리카노 행의 판매수량 10개(매장 0 / 포장 10), 순매출 39,000원, 식재료비 4,968원, 포장비 1,664원, 수수료 600원, 공헌이익 31,768원, 마진율 81.5%가 표시된다. 위쪽 메뉴 공헌이익도 31,768원이다.

### 완료한 확인: U04 판매 수량 수정

‘판매 기록’으로 돌아가 2026-09-19의 직접 입력 아메리카노·포장 행의 연필(수정) 버튼을 누른다. 수량만 10에서 5로 바꾸고 단가 4,000원·전체 할인 1,000원·수수료 600원을 유지한 채 ‘수정 저장하기’를 누른다.

### 완료한 확인: U06 삭제 확정과 저장 유지

같은 아메리카노·포장 행에서 휴지통(삭제) 버튼을 다시 누르고 ‘삭제 확정’을 누른 뒤 브라우저를 새로고침한다.

### 완료한 확인: U08a 잘못된 수량의 저장 차단

‘신규 판매 기록 추가’를 눌러 날짜 2026-09-19, 메뉴 아메리카노, 채널 포장, 수량 0, 단가 4,000원, 전체 할인 0원, 수수료 0원을 입력하고 ‘기록 저장하기’를 누른다. 기존 U08은 한 번에 한 오류씩 확인하도록 수량(U08a)과 빈 수수료(U08b)로 나누어 안내한다.

예상 결과: 수량 오류 안내가 표시되고 입력창이 유지되며 기록이 저장되지 않는다. 다음 빈 수수료 확인을 위해 입력창을 그대로 둔다.

확인 결과: 2026-10-12 사용자가 “정상”이라고 응답했다. 수량 0의 오류 안내와 저장 차단 확인을 통과로 기록한다.

### 완료한 확인: U08b 빈 수수료의 저장 차단

열려 있는 신규 판매 입력창에서 수량을 1로 바꾸고 결제수수료 칸의 0을 지워 빈칸으로 만든다. 날짜 2026-09-19, 아메리카노·포장, 단가 4,000원, 할인 0원은 유지한 채 ‘기록 저장하기’를 누른다.

예상 결과: 수수료 입력 오류 안내가 표시되고 입력창이 유지되며 기록이 저장되지 않는다. 수수료 없음은 숫자 0으로 명시해야 하며 빈칸을 0으로 처리하지 않는다.

확인 결과: 2026-10-12 사용자가 “정상”이라고 응답했다. 빈 수수료의 오류 안내와 저장 차단 확인을 통과로 기록한다.

- 재고 화면에 기준일의 실제 재고 기록 목록·출처·사유·메모·입고 총 구매금액을 표시한다. 재고 기록 수정·삭제는 추가하지 않았다.
- 신규 실사에 비교 기준이 없으면 실측값은 이후 기준으로 사용하되 당시 차이는 계산 불가로 저장·표시한다. 내부 이벤트의 증감 자리에는 0을 보관하지만 실측 기준 계산에서 더하지 않으며, 비교값의 null을 실제 차이 0으로 표시하지 않는다.
- 저장 자료가 손상되면 일반 입력·백업을 중단하고 외부 유효 백업으로 복구하는 경로를 제공한다. 현재 저장 버전·변경 번호를 읽을 수 없는 경우에는 안전한 복원을 막고 기존 자료를 삭제하지 않는다.
- 운영 보안 정책에서 동적 코드 생성 없이 자료를 검사하도록 Zod의 `jitless` 설정을 적용했다. Vercel 배포용 헤더 설정을 작성하고 빌드 결과를 로컬에서 같은 보안 헤더로 검사했다. 실제 Vercel 배포는 별도다.
- 입력창은 날짜 입력에 초점을 옮기고 취소·닫기·새로고침에서 미저장 값을 보호한다.

### 검수 중 발견한 문제와 수정

동시에 실행한 개발용·운영용 Chrome 검사가 기본 결과 폴더를 공유해 첫 검사의 trace 파일 저장 중 ENOENT가 발생했다. 기능 성공을 이유로 이 실패를 통과로 기록하지 않았다. 운영 검사의 출력 폴더를 `production-test-results`로 분리하고 최종 검사들을 다시 실행했다. 운영 검사 포트가 다른 프로젝트와 겹친 경우에는 해당 프로젝트를 종료하지 않고 검사 포트를 5194로 바꾸었다. 이 폴더와 개발 검사 결과 폴더는 GitHub 제외 규칙에 포함했다.

## 12. 최종 검사 판정

날짜 입력 초점 검사를 추가하는 과정에서 오류 입력 후 수정 단계에도 ‘입력창을 처음 열 때’의 초점 조건을 잘못 적용한 검사 2개가 실패했다. 초점 검사를 창을 여는 시점에만 적용하도록 고쳤고, 입력 오류·저장 차단 검사는 유지했다. 최종 전체 실행에서는 실패·재시도 통과·건너뜀 없이 모두 통과했다.

| 최종 검사 | 결과 | 근거 |
| --- | --- | --- |
| 계산·검증·저장 | **116개 통과** | Vitest 5개 파일. 기존 78개 + EPIC 3 추가 38개 |
| Chrome 기능·속도 | **19개 통과**, 실패·건너뜀·flaky 0 | `test-results/e2e-results.json`, 2026-10-12 14:54:45 KST 시작, 57.1초 |
| 운영 빌드·보안 헤더 | **1개 통과**, 실패·건너뜀 0 | `production-test-results/results.json`, 14:53:48 KST 시작, 3.2초. 비용 저장·재접속·실제 다운로드·파일 검사·복원, CSP 위반·외부 요청 없음 |

### 실제 결과 재현

- 우유 1,000ml 입고 시 잔량 증가·단위 원가 3.2원/ml·총 구매금액 보관을 확인했다. 입고 가격을 기존 가격이력·운영비에 더하지 않았다.
- 판매 공헌이익 31,768원·광고비 10,000원·우유 폐기 200ml(626원)에서 매장 손익 **21,142원**을 실제 Chrome 화면으로 확인했다.
- 별도 작은 가상 재고 자료에서 마감 실측 6,200ml와 다음 날 200ml 사용 후 **6,000ml**를 실제 Chrome 화면으로 확인했다. 6,400ml→6,200ml의 기준 사례는 계산 검사로 함께 확인했다.
- 전체 백업 후 비용을 변경하고 복원했을 때 판매·비용·재고·원가 근거·실사 비교·출처·정책의 전체 내용이 백업과 일치했다. 변경 번호만 현재 저장소 기준으로 증가했다. 메뉴 공헌이익·손익·잔량도 백업 당시 값으로 돌아왔으며 재접속 후 샘플을 다시 합치지 않았다.

### 최종 속도 측정

제공 가상 자료 전체·이 컴퓨터·로컬 개발 서버·Chrome에서 측정했다. 선택/저장 조작부터 결과 표시까지의 측정이며 파일 선택·사용자 확인 대기 시간은 제외한다.

| 동작 | 측정값 | TRD 목표 |
| --- | ---: | ---: |
| 월 손익 조회 | 240ms | 500ms 이내 |
| 전체 재고 조회 | 199ms | 1초 이내 |

## 13. 최종 완료 상태와 남은 마무리

- EPIC 1: 사용자 화면 확인 완료 유지.
- EPIC 2: **완료 — 사용자 검수 위임에 따른 담당자 검수**.
- EPIC 3: **완료 — 사용자 검수 위임에 따른 담당자 검수**.
- PRD의 2차 기능인 엑셀·전망·발주·기간 확장·기준정보 편집·여러 기기 공유는 추가하지 않았다.
- 실행용 로컬 서버와 브라우저를 열어 두었다. 사용자에게 추가 수동 검사를 요구하지 않는다.
- GitHub 보관·Vercel 운영 배포와 운영 주소의 재접속·백업·복원 검사는 **미완료인 별도 마무리 작업**이다. `vercel.json`과 로컬 운영 빌드 검사는 준비했지만 배포된 것으로 기록하지 않는다. EPIC 기능 완료를 전체 운영 배포 완료로 표현하지 않는다.
