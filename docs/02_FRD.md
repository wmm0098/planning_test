# 카페 판매·손익·재고 관리 기능 요구사항(FRD)

작성일: 2026-10-12  
상태: PRD의 1차 범위를 유지한 기능 명세. 새 계산·처리 기준은 사용자의 “추천대로 해줘” 지시에 따라 선택한 추천안이다. 새 기능을 승인한 것으로 해석하지 않는다.

## 1. 이 프로그램이 하는 일

운영자가 판매와 비용을 입력·수정·삭제하고, 메뉴가 남기는 금액과 일·월 단위 매장 손익을 확인한다. 재료의 입고·폐기·실측 수량을 기록하여 기준일의 잔량과 차이를 확인한다. 기록은 운영용 컴퓨터에 저장하고, 전체 자료를 파일로 백업·복원한다.

핵심 사용 순서는 **판매 저장 → 메뉴 수익성 확인 → 같은 기간 손익 확인 → 기간 마지막 날의 재료 잔량 확인**이다. 한 매장·한 사용자·컴퓨터 한 대를 대상으로 한다.

공헌이익은 이 문서에서 ‘재료·포장·결제수수료를 반영한 메뉴 자체의 남는 금액’을 뜻한다. 매장 손익은 여기에 공통 운영 비용과 폐기 손실까지 반영한 운영 참고 금액이다. 세금이나 정밀한 재고 회계까지 포함한 결산 순이익으로 부르지 않는다.

### 읽은 근거

- `docs/01_PRD.md`: 기능 범위, 비용 포함 범위, 과거 기록 보존, 저장·복원 요구.
- `design/_1/screen.png`, `design/_1/code.html`: 재고 목록과 실사 입력 창.
- `design/_2/screen.png`, `design/_2/code.html`: 기간 실적·손익표.
- `design/_3/screen.png`, `design/_3/code.html`: 메뉴 수익성.
- `design/_4/screen.png`, `design/_4/code.html`: 판매 목록과 판매 입력 창.
- `design/prep_cafe/DESIGN.md`: 공통 표시·상태·입력창 지침.
- `date`의 데이터 설명과 JSON: 실제 식별번호·기록 구조·가격·레시피 확인.

시안은 화면 구성의 근거다. HTML에 저장 버튼이 있거나 계산 완료 문구가 있다는 사실만으로 저장·계산이 구현되어 있다고 보지 않는다. 시안의 숫자를 검사 정답으로 사용하지 않는다.

## 3. 시안과 다른 부분의 처리

사용자의 추천 위임에 따라 **PRD를 우선하고 필수 기능을 보완**한다. 새 기능과 2차 기능을 1차에 추가하지 않는다. 원본 시안 파일과 PRD는 수정하지 않는다.

시안 숫자에도 차이가 있다. 판매 화면 상단 순매출 428,000원과 표 소계 474,700원이 다르고, 수익성 화면의 8개 메뉴 매출 합계는 16,675,000원인데 표시 합계는 12,480,000원이다. 구현 시 같은 조회 대상의 실제 계산값으로 표·합계·카드를 함께 갱신한다.

## 4. 공통 입력·계산·표시 기준

### 4.1 자료와 입력의 의미

- 날짜는 한국 날짜 기준으로 처리한다. 일 조회는 해당 날짜 전체, 월 조회는 해당 월의 첫날부터 마지막 날까지다.
- 판매 한 줄은 날짜·메뉴·매장/포장별 하루 합계다. 수량은 주문 수가 아니다.
- 금액은 원·부가세 제외다. 판매가·할인·수수료·일별 비용은 0 이상의 정수 금액이며, 할인은 한 줄 전체의 금액이다. 할인 입력은 양수로 받고 화면에 차감임을 표시한다.
- 판매수량과 재고의 ‘개’ 단위는 정수다. g·ml는 소수 셋째 자리까지 받는다. 단위는 재료 선택으로 정해지며 사용자가 바꾸지 않는다. 시안의 10ml 증분 제한은 사용하지 않는다.
- 빈칸은 미입력이다. 할인·수수료가 없으면 사용자가 0을 확인해서 입력한다. 실제 재고 0은 유효하다.
- 신규 판매·비용·입고·폐기는 수량 또는 금액이 양수여야 한다. 무료 판매는 단가 0 또는 전액 할인으로 허용한다. 취소·반품용 음수 판매는 1차에 추가하지 않는다.
- 신규 입력은 오늘 이전 또는 오늘 날짜를 허용한다. 미래 날짜는 실적 기록으로 저장하지 않는다. 제공 달력 밖 과거·현재 날짜는 달력 상태가 없음을 알리고 잠정 기록으로 취급한다. 달력을 편집하는 새 기능은 추가하지 않는다.

### 4.2 금액 자리수와 원본 보존

추천 계산 기준: 재료의 단위 원가와 메뉴 한 개의 원가는 소수 정밀도를 유지한다. 판매 한 줄의 식재료비·포장비, 폐기 한 건의 손실 금액은 최종적으로 원 단위 반올림한다. 화면 합계는 이 최종 금액들의 합으로 한다. 양수 금액의 0.5원은 올린다. 비율은 반올림하여 소수 첫째 자리까지 표시한다.

예: 원두 1,000g에 24,840원이면 1g 원가는 24.84원이며, 아메리카노 한 개의 20g 원가는 496.8원이다. 이를 먼저 497원으로 만들지 않고, 판매수량을 적용한 뒤 원 단위로 반올림한다.

가져온 당시 단가·원가·순매출·수수료·비용·실사조정값은 원본 값으로 보존한다. 계산용 결과와 반올림은 별도로 만든다. 기존 기록의 순매출과 입력 기반 계산값이 다르면 원본 순매출을 유지하고 ‘기존 기록 값 차이’를 알린다. 사용자 수정 저장 때만 변경 대상의 입력과 계산값을 일치시킨다.

### 4.3 저장 전후 동작

입력 중 미리보기는 ‘저장 전 계산’이다. 미래 매출 전망을 뜻하지 않는다. 저장 성공 전에는 목록·합계·재고에 반영하지 않는다. 저장 성공 후에만 관련 화면을 갱신한다. 취소·닫기에서 입력이 바뀌었다면 ‘입력을 버리고 닫을까요?’를 확인하며, 취소하면 입력창을 유지한다.

공통 검증: 필수값, 날짜, 숫자, 범위, 식별번호 연결, 재료 단위, 가격이력·레시피 유무를 검사한다. 잘못된 값이 있으면 해당 입력과 이유를 표시하고 저장하지 않는다. 저장 중 중복 클릭은 같은 기록을 여러 번 만들지 않는다. 실패 시 기존 저장 자료와 결과를 유지하고 입력값을 남겨 재시도할 수 있게 한다.

## 5. 기능별 동작

### F01. 제공 자료 최초 반영 — M1

**행동:** 처음 프로그램을 사용한다. **처리:** 제공 JSON을 초기 자료의 한 형식으로 사용한다. 엑셀과 JSON을 함께 더하지 않는다. 자료번호·버전과 고유 기록번호를 확인하며, 이미 저장한 자료가 있으면 샘플을 다시 넣지 않는다.

**화면 결과:** 실제 메뉴·재료·공급사, 판매·비용·재고 기록과 ‘가상 매장 샘플’ 출처, 2025-07-01~2026-09-18 실적 기간을 확인한다. 새로 입력한 기록은 ‘직접 입력’ 출처로 구분한다. **저장 결과:** 모든 제공 기록, 가격이력·레시피·달력·월 계획·자료정보를 저장한다. 내려받는 파일은 없다.

**예외:** 초기 자료가 손상되거나 식별번호가 중복·누락되면 일부만 조용히 저장하지 않는다. 실패 항목을 안내한다. 기존 자료가 있다면 그대로 유지한다. 복원 후에도 샘플을 다시 합치지 않는다.

### F02. 화면 이동·조회·상태 — M1, M5

**행동:** 판매 관리, 메뉴 수익성, 기간 실적·손익, 재고 관리, 백업 메뉴를 선택한다. **처리:** 해당 화면을 열고, 판매·수익성·손익에는 같은 일·월 조회 기간을 전달한다. 기간 손익에서 재고로 이동하면 조회 종료일을 재고 기준일로 전달한다.

**입력:** 일/월, 날짜 또는 월. 판매 화면은 메뉴·채널·메뉴명 검색, 수익성은 전체/음료/디저트, 재고는 재료명·공급사 검색을 사용한다. 재고의 추가 필터 아이콘은 별도 기능을 부여하지 않고 제외한다. 판매 목록 ‘이전/다음’은 현재 필터 결과의 페이지를 이동하며 합계는 페이지가 아닌 전체 필터 결과 기준이다. 페이지당 50건을 추천 기준으로 한다.

**결과:** 조회 기간, 포함된 기록 범위, 출처·마감 상태와 단위를 표시한다. 필터 변경은 기록을 바꾸지 않고 파일도 만들지 않는다. ‘메뉴 수익성 이동’과 ‘기간 실적·손익’ 링크는 같은 기간으로 이동한다.

**예외:** 결과가 없으면 ‘조회 기록 없음’을 표시한다. 불완전한 기록을 판매 0으로 표시하지 않는다. 입력 중 이동은 입력 폐기 확인을 거친다. 손익 합계와 메뉴 명세의 필터가 다르면 필터 범위를 표시하여 숫자 차이를 설명한다.

### F03. 판매 등록 — M2

**버튼:** ‘신규 판매 기록 추가’, ‘간편 입력’은 동일한 등록창을 연다. ‘기록 저장하기’는 검증·저장, ‘취소’·닫기는 취소다.

| 입력칸 | 동작과 필수 조건 |
| --- | --- |
| 판매 날짜 | 필수. 조회일을 제안하고 사용자가 변경 가능 |
| 메뉴 | 제공된 8개 메뉴 중 선택. 선택 전에는 저장 불가 |
| 판매 채널 | 매장/포장 중 필수 선택. 신규 창은 매장을 기본 제안 |
| 판매 수량 | 1 이상의 정수. 하루의 해당 메뉴·채널 판매수량 |
| 판매 단가 | 메뉴 기준가를 제안하고 사용자가 당시 단가로 수정 가능 |
| 할인 금액 | 한 줄 전체의 할인액. 0 이상, 수량×단가 이하 |
| 결제수수료 | 확인한 한 줄 전체 금액. 자동 비율 계산 없음. 미입력은 저장 불가, 없음은 0 |

**계산:** 6절 C1~C3. 날짜·메뉴·채널을 바꾸면 적용 레시피·가격과 미리보기를 갱신한다. 레시피 버전과 당시 개당 식재료·포장 원가를 기록에 함께 보관한다.

**화면 결과:** 저장 후 날짜·메뉴·채널·수량·당시 단가·할인·순매출·수수료·한 줄 식재료비·포장비를 표시한다. ‘금일’ 고정 표시 대신 조회일 또는 조회월을 표시한다. 합계·수익성·손익·레시피 사용량에 따른 잔량을 갱신한다. **저장 결과:** 새 판매번호, 입력값·당시 기준·출처를 저장한다. 별도 파일 다운로드는 없다.

**예외:** 같은 날짜·메뉴·채널이 있으면 중복 저장을 막고 기존 기록 수정을 안내한다. 판매 한 줄이 하루 합계이므로 자동으로 더하거나 덮어쓰지 않는다. 원가 기준이 없으면 저장을 막고 부족한 재료·가격·레시피를 알린다. 수수료가 순매출보다 크면 경고 후 사용자 확인을 받아 저장할 수 있다. 재고가 음수가 되어도 실제 판매 기록은 저장하되 F10의 수량 확인 안내를 표시한다.

### F04. 판매 수정·삭제 — M2

**행동:** 목록의 ‘수정’을 누르면 원래 입력값과 당시 원가 기준을 연다. 날짜·메뉴·채널을 유지한 수량·단가·할인·수수료 수정은 기존 개당 원가를 유지한다. 날짜·메뉴·채널 변경은 바뀐 조건의 원가 기준을 적용하고 변경 전후를 보여준다. 저장은 F03 검증을 다시 거친다.

**삭제:** 날짜·메뉴·채널·수량·순매출과 ‘수익성·손익·기록상 잔량도 바뀝니다’를 확인한 후 삭제한다. 취소하면 그대로 유지한다. 거래 반품을 새로 만드는 동작이 아니다.

**결과:** 수정은 같은 판매번호를 유지하고 삭제는 활성 기록에서 제거한다. 기존 기여분을 제거한 후 변경 결과를 반영하여 이중 계산을 막는다. 실측 수량은 바꾸지 않는다. 자동으로 과거 전체 판매 원가를 재평가하지 않는다. 파일 다운로드는 없다.

**예외:** 변경 후 날짜·메뉴·채널이 다른 판매와 겹치면 저장하지 않는다. 대상이 이미 없으면 안내하고 목록을 갱신한다. 저장 실패 시 수정 전 기록 유지. 실사 이전 판매가 바뀌면 실사 차이 확인값은 바뀔 수 있지만 실측 기준 이후 잔량에는 F09의 기준을 적용한다.

### F05. 비용 입력·수정·삭제 — M3

시안의 ‘비용 영수증 등록’을 ‘비용 기록 입력’으로 해석한다. 손익 화면 안에서 비용 목록과 입력·수정·삭제를 제공하는 것을 추천한다. 새 독립 기능이나 영수증 이미지 첨부는 추가하지 않는다.

**입력:** 귀속 날짜(어느 날의 비용인지), 제공된 8개 비용항목, 양수 정수 금액. 출처는 직접 입력, 기록 방식은 ‘직접 입력 비용’으로 자동 구분한다. 제공 자료의 ‘월비용 일할 배분’ 표시는 유지한다.

**처리·결과:** 기간과 비용항목별 금액을 합산한다. 월비용계획을 다시 나누어 더하지 않는다. 비용 목록의 항목·금액·날짜·출처·기록 방식과 손익을 갱신하고 비용번호·입력값을 저장한다. 파일 다운로드는 없다. 수정·삭제는 판매와 같은 저장·취소·확인 원칙을 따른다.

**예외:** 같은 날짜·항목·금액이 있으면 중복 가능성을 알리고, 별개 비용이라고 확인할 때만 저장한다. 기존 월비용 배분 항목이 있는 날짜에는 ‘기존 비용을 수정하려는 경우 수정 기능을 사용하세요’를 안내한다. 프로그램이 실제 중복인지 추정하여 덮어쓰지 않는다. 재료 구매는 입고에서 기록하도록 안내하고 일반 운영비에 추가하지 않는다. 금액 0·음수·비용항목 미선택은 저장하지 않는다.

### F06. 메뉴별 수익성 — M4

**행동:** 기간과 전체/음료/디저트를 선택한다. **처리:** C4에 따라 메뉴별·채널별 판매수량, 순매출, 식재료비, 포장비, 수수료, 공헌이익·마진율을 계산한다.

**화면 결과:** 메뉴 명세표와 조회 대상의 총 판매수량·순매출·직접비용·공헌이익·전체 마진율을 표시한다. 공통 비용과 폐기 손실은 메뉴에 배분하지 않음을 안내한다. ‘원가율’은 식재료비 비율이라고 이름을 명확히 하고, 직접비용 비율과 혼동하지 않는다. 기본 목록은 메뉴번호 순이며 등급·효자 메뉴·순위 정렬은 없다. 파일은 만들지 않고 결과는 저장된 기록에서 재현한다.

**예외:** 판매 없는 메뉴는 수량·금액 0, 마진율은 ‘계산 대상 없음’으로 표시한다. 순매출 0에서는 나눗셈 비율을 계산하지 않는다. 필요한 원가가 빠진 기존 자료는 알려진 매출을 표시하되 해당 비용·공헌이익과 전체 관련 합계를 ‘일부 계산 불가’로 표시한다. 누락을 0으로 채우지 않는다.

### F07. 기간 실적·매장 손익 — M5

**행동:** 일 또는 월을 선택한다. ‘비용 기록 입력’은 F05, ‘폐기 등록’은 F08을 열고 선택 기간의 날짜를 제안한다.

**처리:** C5에 따라 순매출, 식재료비·포장비·수수료, 공헌이익, 운영비 8개 항목, 폐기 손실, 매장 손익과 손익률을 계산한다. 비용을 판매가 있는 날짜에만 제한하지 않는다. 휴무일 비용도 해당 기간 비용이면 포함한다.

**화면 결과:** 같은 대상의 요약과 상세 내역을 표시한다. 마감된 실적과 미마감일에 이미 입력한 실적을 분리하고, 미마감 실적을 포함한 전체에는 ‘잠정 포함’ 표시를 한다. 미래 예상 순이익·보고서 다운로드는 제공하지 않는다. 저장 자료 변경 없이 조회만 하며 다운로드 파일은 없다.

**날짜 상태:** 영업달력의 영업 여부와 마감 여부를 따로 사용한다. 미래·미마감의 기록 없음은 0이 아니다. 마감·영업일인데 판매 행 자체가 없으면 누락 확인 대상으로 둔다. 제공 판매 0 행이 있는 것은 실제 0 판매로 취급한다. 휴무일 판매가 있으면 상충 안내를 표시하고 이미 기록된 판매를 조용히 버리지 않는다. 신규 기록이 미마감이면 입력된 금액의 잠정 실적만 계산하며 전망하지 않는다.

**예외:** 요청월 일부만 자료가 있으면 요청월과 실제 기록 범위를 함께 표시한다. 2025년 7월 이전 자료 없음과 2026년 9월 19일 이후 미마감을 구분한다. 원가·폐기 단가 누락은 해당 손익의 완전성을 제한한다. 순매출 0인 기간도 비용·폐기·손실 금액은 표시하며 비율만 계산 대상 없음이다. 확정이라는 표현은 기록 완전성이 확인된 부분에만 사용하며 수정 잠금은 하지 않는다.

### F08. 재료 입고·폐기 기록 — M6

**버튼:** 재고의 ‘입고 기록’, ‘폐기 기록’, 손익의 ‘폐기 등록’은 각각 최소 입력창을 연다.

| 입력 | 입고 | 폐기 |
| --- | --- | --- |
| 날짜·재료 | 필수, 재료 단위 자동 표시 | 필수, 재료 단위 자동 표시 |
| 수량 | 실제 들어온 양을 양수로 입력 | 버린 양을 양수로 입력 |
| 금액 | 이번 입고 총 구매금액 필수, 0 허용 | 해당 날짜 가격이력으로 손실 계산, 직접 금액 입력 없음 |
| 공급사 | 해당 재료의 공급사를 제안, 제공 3개 공급사 중 선택 | 입력 불필요 |
| 사유 | 선택 메모 | 폐기 이유 필수 |

**처리:** 입고는 양의 증감수량, 폐기는 음의 증감수량으로 저장한다. 입고 단위 원가는 구매금액÷입고 수량이며 입고 기록과 백업에 보관한다. 입고 구매금액을 운영비에 다시 더하지 않는다. 입고 가격이 기존 가격이력과 달라도 이번 입고의 정보로 보관하며 기준 가격이력이나 과거 판매를 자동 변경하지 않는다. 폐기 손실은 C6의 가격이력 기준이다.

**결과:** 기록 목록·잔량·최종 입고 정보·기간 폐기 손실·손익을 갱신한다. 기록번호·날짜·재료·단위·증감·사유·해당 원가 정보를 저장하고 별도 파일은 만들지 않는다.

**예외:** 단위 불일치·0 수량·음수 입력은 저장하지 않는다. 폐기가 기록상 잔량보다 크면 수량과 미기록 입고 가능성을 확인하도록 경고한 뒤 확인 시 저장한다. 실제 폐기 사실을 잔량 부족만으로 버리지 않는다. 폐기 가격이 없으면 금액은 계산 불가로 알리되 수량 기록은 저장하고 손익을 불완전으로 표시한다. 같은 날짜·재료·유형·수량은 중복 확인을 거친다. 재고 기록 수정·삭제 기능은 PRD에 없으므로 새로 추가하지 않는다.

### F09. 실제 재고 입력·대조 — M6

**버튼:** ‘실제 재고 입력’은 재료를 고르는 창, 행의 ‘실사조정’은 그 재료가 선택된 같은 창을 연다. ‘실사 기록 및 잔량 동기화’는 검증 후 저장하며 외부 서비스와 동기화하지 않는다.

**입력:** 실제 재고를 센 날짜, 재료, 실측 수량, 차이 발생 사유와 선택 메모. 시안의 읽기 전용 ‘22:00’ 대신 날짜를 선택한다. 1차는 하루 마감 후 실측으로 해석하고 실제 시각 정보를 임의로 만들지 않는다. 사유는 자연 손실·레시피 초과 사용·미기록 폐기·기타 중 사용자 선택으로 받되 원인을 자동 확정하지 않는다.

**미리보기:** 실사 직전 기록상 잔량과 실측값, C7의 차이를 표시한다. 예: 기록 6,000ml, 실측 5,800ml이면 차이는 -200ml다. 다른 날짜의 최근 실측값과 현재 잔량을 직접 빼서 오늘의 차이로 표시하지 않는다.

**저장:** 실측 수량, 당시 비교 잔량·차이·사유를 보존한다. 해당 재료는 그날 마감 실측 수량을 이후 잔량 계산의 기준으로 사용한다. 다른 재료의 기준은 바꾸지 않는다. 실사 차이를 폐기 손실로 자동 전환하지 않는다. ‘미기록 폐기’ 사유를 골라도 별도 폐기 기록을 자동으로 만들지 않는다.

**예외:** 음수 실측·잘못된 단위는 저장하지 않는다. 0 실측은 허용한다. 같은 재료·날짜의 실사는 중복 저장을 막는다. 차이 0도 실사 사실을 저장한다. 기준 재고·레시피가 없으면 차이는 계산 불가로 표시하되 실측값은 기준으로 저장할 수 있다. 과거 판매 변경 후에는 원래 실측값·당시 비교값을 보존하면서 현재 자료로 다시 본 차이를 별도 표시한다. 변경일 이전의 저장된 차이를 덮어쓰지 않는다.

### F10. 기준일 재고 잔량 — M6

**행동:** 기준일을 선택하거나 재고 관리로 이동한다. 시안에 빠진 기준일 입력을 필수 보완한다. **처리:** C7에 따라 기준일 마감 잔량을 계산한다. 판매수량과 레시피·채널로 재료 소진량을 구한다. 미래일 잔량을 판매 전망으로 생성하지 않는다.

**화면 결과:** 실제 자료의 11개 재료별 단위·잔량·공급사·최종 입고일 및 단위 원가·최근 실사 날짜와 수량을 표시한다. 차이는 해당 실사일의 비교값으로 이름 붙인다. 총 재료 품목 수·해당 월 폐기 손실·최근 실사일은 실제 기록으로 표시한다. 여러 날짜의 일부 실사를 ‘전수조사 완료’로 부르지 않는다. 파일 다운로드는 없다.

**예외:** 원두 g와 우유 ml를 하나의 잔량 합계로 더하지 않는다. 음수 잔량은 0으로 바꾸지 않고 ‘기록상 음수: 판매·입고·폐기 확인’으로 표시한다. 이는 안전재고 기반 발주 경고가 아니다. 시작 재고도 실측 기준도 없는 재료는 잔량 계산 불가로 표시한다. 마지막 기록일 이후 조회는 ‘기록 기준, 미기록 변동 미포함’ 표시를 한다. 실사 이후 실제 움직임이 미입력일 수 있으므로 현재 실물과 같다고 보장하지 않는다.

### F11. 저장·재접속 — M7

저장 버튼은 입력을 검증한 뒤 전체 변경이 성공할 때만 ‘저장됨’으로 알린다. 성공 전에는 저장 상태를 표시하지 않는다. 입력 중 미저장 값은 자동 보존된 기록으로 표시하지 않는다. 각 저장 성공 후 관련 결과를 갱신하고 다시 접속해도 해당 기록을 복구한다.

기술과 저장 위치의 구체적인 방식은 후속 개발 설계에서 정한다. 사용자 관점에서는 컴퓨터 한 대의 작업 자료가 보존되어야 한다. **예외:** 저장 공간 부족·접근 불가·저장 자료 손상은 원인과 영향 범위를 안내하며 신규 샘플로 덮어쓰지 않는다. 저장 실패 시 이전 값 유지, 입력 재시도 가능. 동시에 열린 창에서 저장 자료가 변경되었다면 오래된 내용으로 덮어쓰지 않고 다시 조회하도록 안내한다.

### F12. 전체 백업 — M7

**행동:** 백업 메뉴 또는 상단 백업 아이콘에서 ‘전체 백업 다운로드’를 선택한다. **처리:** 저장 완료된 시점의 전체 자료와 운영 기준을 한 번에 묶는다. 미저장 입력이 있으면 먼저 저장하거나 버리도록 안내하고, 저장 실패 상태에서는 완전한 최신 백업처럼 표시하지 않는다.

**파일 결과:** 추천 형식은 JSON이며 파일명은 `prep-cafe-backup-YYYYMMDD-HHmmss.json`이다. 매장·자료번호·백업 형식 버전·한국 기준 생성시각, 공급사·메뉴·재료·레시피·가격이력·달력·초기재고·판매·비용·재고기록·월계획·출처·실측 기준·운영 기준을 포함한다. 당시 원가와 고유 기록번호를 보존한다. 화면 필터와 페이지는 복원 대상 데이터가 아니다. 조회 결과를 사진처럼 저장하는 엑셀 보고서와 구분한다.

**화면 결과:** 다운로드 시작 사실과 백업 시점을 알린다. 브라우저가 실제 파일 저장을 확인하지 못하면 ‘컴퓨터에 저장 완료’라고 단정하지 않는다. **예외:** 파일 생성 실패는 기존 기록을 바꾸지 않는다. 저장되지 않은 입력은 백업에 포함하지 않는다.

### F13. 전체 복원 — M7

**행동:** ‘백업 파일 선택’에서 JSON을 고르고 ‘복원’을 누른다. **처리:** 파일 읽기·내용 검사 후 매장명·백업시각·자료 기간·기록 수를 보여주며 ‘현재 기록 전체가 백업 시점으로 교체됩니다’를 확인한다. 추천 정책은 전체 교체이며 합치기를 추가하지 않는다. 취소 시 그대로 유지한다.

**검사:** 지원 버전, 필수 자료, 중복 번호, 메뉴·재료·공급사 연결, 유효 날짜·단위·금액·실측 수량을 검사한다. 수수료·원가의 기존 빈칸이나 음수 실사조정 등 자료 구조상 허용한 값은 그 의미대로 검사한다. 깨진 자료와 계산 정보가 일부 부족한 유효 자료를 구분한다.

**결과:** 전체 교체와 저장이 모두 성공한 뒤 목록·수익성·손익·잔량을 새 자료에서 다시 계산한다. 백업 당시 입력과 기준으로 동일 결과를 재현한다. 백업된 샘플과 직접 입력 출처도 유지한다. 새 다운로드 파일은 없다.

**예외:** 단순 확장자만 믿지 않는다. 손상 JSON·미지원 버전·잘못된 연결·다른 매장 자료는 복원을 막고 이유를 알린다. 초기 제공 JSON은 전용 백업 정보가 없으므로 복원 파일로 받지 않는다. 검사·저장 중 실패하면 현재 전체 자료를 유지하고 부분 복원하지 않는다. 유효한 백업에 계산 정보 누락이 있으면 그 제한을 미리 안내하며 복원 후에도 ‘일부 계산 불가’를 유지한다. 복원 중 입력·다른 복원을 막아 혼합을 방지한다.

## 6. 계산 명세와 쉬운 예시

아래는 이번 FRD에서 추천 지시에 따라 선택한 방법이다. 샘플에 있던 정책으로 소급 해석하지 않는다. 모든 ‘합계’는 명시된 조회 대상 기록을 더하며, 다른 단위의 수량을 합산하지 않는다.

### C1. 판매 금액

- 할인 전 금액 = 판매수량 × 당시 판매 단가.
- 순매출 = 할인 전 금액 − 한 줄 전체 할인금액.
- 수수료는 입력된 확인 금액. 고정 요율로 만들지 않는다.

예: 10개×4,000원, 전체 할인 1,000원이면 순매출 39,000원. 수수료를 600원이라고 입력하면 그대로 사용한다. 할인 1,000원을 개당 할인으로 해석하지 않는다.

### C2. 당시 단위 원가와 메뉴 원가

재료별로 판매 날짜 이전 또는 당일에 시작한 가격이력 중 가장 최근 것을 적용한다. 미래 가격을 가져오지 않는다. 기준 단위 원가 = 구매 묶음 가격÷구매 묶음 용량. 해당 메뉴의 기록된 레시피 버전에서 전체 채널 재료와 선택 채널 전용 재료만 사용한다.

- 개당 식재료 원가 = 적용 식재료 각각의 ‘레시피 사용량×단위 원가’ 합계.
- 개당 포장 원가 = 적용 포장재 각각의 ‘레시피 사용량×단위 원가’ 합계.
- 이 자료의 포장재는 I10 포장컵세트·I11 디저트포장세트이며 나머지는 식재료다. 이름의 일부 글자로 임의 분류하지 않는다.
- 한 줄 식재료비·포장비 = 당시 개당 원가×판매수량 후 각각 원 단위 반올림.
- 재료 소진량 = 적용 레시피 사용량×판매수량. 금액 반올림과 관계없이 수량 단위를 유지한다.

예: 2026-09-18 아메리카노 포장 10개는 식재료비 4,968원, 포장비 1,664원, 원두 소진 200g·포장컵세트 소진 10개다. 매장 10개이면 포장비·컵 소진은 0이다. 이 값은 시안의 아메리카노 원가 8,800원과 다르다.

레시피가 없거나 단위가 맞지 않거나 적용 가능한 가격이 없다면 원가를 0으로 계산하지 않는다. 가격이력에 같은 재료·적용일이 중복이면 임의로 하나를 선택하지 않는다. 기존 판매는 저장된 당시 원가를 우선한다. R1에 적용일 정보가 없는 사실을 보존하며 존재하지 않는 다른 레시피 버전을 추정하지 않는다.

### C3. 판매 한 줄의 공헌이익

공헌이익 = 순매출 − 식재료비 − 포장비 − 결제수수료.

위 포장 아메리카노 예에서 단가 4,000원·할인 1,000원·수수료 600원이면 공헌이익은 39,000−4,968−1,664−600 = **31,768원**이다. 이는 임대료·인건비 반영 전 금액이다.

### C4. 메뉴별·전체 수익성

메뉴별로 판매수량·순매출·식재료비·포장비·수수료·공헌이익을 각각 합산한다. 매장/포장 수량은 따로 표시한다.

- 마진율 = 공헌이익 합계÷순매출 합계×100.
- 식재료 원가율 = 식재료비 합계÷순매출 합계×100.
- 직접비용 비율 = (식재료비+포장비+수수료) 합계÷순매출 합계×100.
- 전체 마진율도 전체 금액에서 계산한다. 메뉴별 비율의 단순 평균을 쓰지 않는다.

예: 매출 1,000원·공헌이익 900원인 메뉴와 매출 9,000원·공헌이익 900원인 메뉴의 전체 마진율은 18%다. 90%와 10%의 평균인 50%가 아니다. 순매출 0은 비율 ‘계산 대상 없음’, 공헌이익 음수는 그대로 표시한다.

### C5. 일·월 매장 손익

- 운영비 = 조회 기간 귀속일의 비용기록 금액 합계. 8개 항목별 내역을 표시한다.
- 폐기 손실 = 조회 기간 폐기 기록의 C6 손실 금액 합계.
- 매장 손익 = 공헌이익 합계 − 운영비 − 폐기 손실.
- 손익률 = 매장 손익÷순매출 합계×100. 순매출 0은 비율 계산하지 않는다.

월비용계획은 더하지 않고, 기존 날짜별 비용을 영업일 기준으로 다시 배분하지 않는다. 임차료·인건비를 메뉴에 배분하지 않는다. 입고 구매금액과 실사 차이 금액도 더하지 않는다. 예: 공헌이익 31,768원, 운영비 10,000원, 폐기 손실 626원이면 매장 손익은 **21,142원**이다.

마감·미마감 부분의 순매출과 비용은 같은 날짜 범위로 묶는다. 기간 전체를 조회하면 미마감 입력분은 별도 잠정 부분으로 보여준다. 판매 누락·필수 비용의 입력 여부를 프로그램이 모르면 완전한 결산이라고 표현하지 않는다.

### C6. 폐기 손실

추천 기준은 **폐기 날짜의 가격이력 단위 원가**다. 폐기 한 건 손실 = 버린 수량×그날 단위 원가, 원 단위 반올림. 입고 건마다의 실제 매입 원가를 추적하는 정밀 평가나 자동 평균 원가 계산은 추가하지 않는다.

예: 2026-09-18 우유 200ml 폐기, 1,000ml 가격 3,132원이면 손실은 626.4원을 반올림한 **626원**이다. 단가가 없으면 수량 기록은 유지하고 손실과 관련 손익을 불완전 표시한다. 실사 부족분을 다시 폐기로 계산하지 않는다. 이미 폐기 기록이 있는 날의 실사는 폐기 반영 후 잔량과 비교한다.

### C7. 재고 잔량과 실사 차이

실측 기준이 없는 구간의 기록상 잔량 = 초기재고 + 누적 입고 − 누적 판매 레시피 사용량 − 누적 폐기. 초기재고는 첫날 영업 전이다. 하루 안의 시각 자료가 없으므로 일중 순서나 시간대별 잔량을 만들어내지 않는다.

마감 실사가 있는 날은 그날 판매·입고·폐기를 먼저 반영한 잔량과 비교한다. **실사 차이 = 실제로 센 수량 − 실사 직전 기록상 잔량.** 실사 저장 후 그날 마감 잔량은 실측 수량이며, 다음 날부터의 판매·입고·폐기를 이 기준에서 반영한다.

예: 우유 초기 6,000ml, 입고 1,000ml, 판매 사용 400ml, 폐기 200ml이면 실사 전 6,400ml. 실측 6,200ml이면 차이 -200ml, 마감 잔량 6,200ml. 다음 날 판매 사용 200ml만 있으면 6,000ml다.

기존 실사 기록에 실측 수량이 있으면 이를 기준으로 사용하며, 실사조정 증감량을 또 더하지 않는다. 실측값 없는 기존 실사조정은 증감량만 반영한다. 같은 재료·날짜에 기준이 충돌하면 오류를 표시하고 임의 기준을 선택하지 않는다.

과거 판매가 바뀌어도 실측 수량은 보존한다. 변경일 이후 첫 실측 전까지 기록상 잔량과 차이를 다시 계산하고, 그 실측 이후에는 실제로 센 수량을 기준으로 유지한다. 저장 당시 차이는 보존하고 현재 재계산 차이와 구분한다. 재고 화면에는 기준일 종료 잔량을 보여주며 기간별 잔량을 더하지 않는다.

## 8. 기능 완료 검사 기준

1. **범위:** PRD M1~M7이 모두 F01~F13에 연결되고, 시안의 제외 버튼이 작동하는 새 기능으로 남지 않는다.
2. **연결:** 포장 아메리카노 예를 저장했을 때 순매출 39,000원·식재료비 4,968원·포장비 1,664원·공헌이익 31,768원과 원두 200g·컵 10개 소진이 판매·수익성·손익·재고에 일치한다.
3. **수정·삭제:** 수량·채널·날짜 변경과 삭제 후 기존 기여분이 중복되지 않고, 다른 메뉴와 실측값은 바뀌지 않는다. 마감 날짜도 명시적 수정 가능하다.
4. **비용:** 직접 비용 저장·수정·삭제 후 손익이 갱신되고, 월 계획·입고 구매금액이 중복되지 않는다.
5. **재고:** C7의 6,400ml·차이 -200ml·실측 6,200ml·다음 날 6,000ml가 재현된다. 실사조정과 실측값을 이중 적용하지 않는다.
6. **예외:** 무료 판매·순매출 0·실측 0·음수 잔량·빈 수수료·누락 가격·중복 판매를 각각 지정한 동작으로 처리한다.
7. **기간:** 2026년 9월 조회에서 18일까지의 기록과 19일 이후 미마감을 구분하고, 실제 미마감 입력은 잠정 결과에만 반영한다. 휴무일 운영비를 빠뜨리지 않는다.
8. **일치:** 카드·명세·합계는 같은 기간·필터와 C1~C7 결과를 사용한다. 비율은 합계에서 계산하고 페이지 변경으로 기간 합계가 바뀌지 않는다.
9. **보존:** 재접속 후 입력값·출처·원가 기준이 유지된다. 저장 실패 때 변경된 합계를 저장 완료로 보여주지 않는다.
10. **파일:** 백업 후 기록을 변경하고 복원하면 백업 당시의 입력·원가·실사·결과가 되돌아온다. 손상·미지원·중복 번호 백업과 복원 중 실패는 현재 자료를 유지한다.

## 9. 결정 상태와 남은 설계

**이번에 추천안으로 선택한 내용:** PRD 우선, 날짜·메뉴·채널별 판매 중복 차단, 전체 할인·확인 수수료 입력, 당시 원가 보존, 가격이력 기준 폐기 손실, 마감 후 실측을 재고 기준으로 사용, 날짜별 비용 사용, 원 단위 반올림·합계 기준 비율, JSON 전체 백업·교체 복원. 새 제품 기능은 추가하지 않았다.

**여전히 미정인 내용:** 2차의 예상 손익 방식, 부족 판정·발주량 계산, 엑셀 양식과 가져오기 규칙, 수익성 등급·순위, 기준정보 변경 정책, 자동 백업·기기 공유. PRD의 2차 목표를 유지하되 승인된 1차처럼 구현하지 않는다.

저장 기술, 실제 화면 배치와 구현 구조는 후속 설계 대상이다. 비용 목록·입고/폐기 창·백업/복원 화면은 기존 필수 기능을 충족하는 최소 보완 요구로 명시했으며, 완성된 시안이 존재한다고 표현하지 않는다. 4시간의 검사·배포 시간을 유지하는 범위에서 구현한다. 범위 밖 기능이 필요해지면 쉬운 예시·선택지·추천 이유를 제시하여 한 번에 하나씩 확인한다.
